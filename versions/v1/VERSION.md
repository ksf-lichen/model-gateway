## V1 核心逻辑（冻结口径）

### 对象关系

```
模型服务 (service)          ← 对外 model / serviceId，调用方只认这个
    └── 源模型 (source)     ← 一条「供应商连接 × 上游模型名」绑定
            ├── baseUrl / apiKey / provider
            └── prices（忙闲时、折扣、输入输出缓存价等）
调用方 API Key              ← 授权可调哪些 service，与上游 Key 分离
callLogs                    ← 真实调用 + 连通性探测费用
```

### 定价挂载点

- **挂在源模型（source）上**，不挂在服务商实体上（V1 没有独立 Provider 表）。
- 计费取**实际命中的那条 source** 的 `prices`。
- 连通性探测产生的 chat 用量记入 callLogs（主体「连通性探测」）。

### 交互特征

- 「接入源模型」向导：连接信息 → 能力 → 价格 → 确认；一条源一次录入。
- 同供应商多模型需重复填 Base URL / Key（或复制再改模型名）。

## 如何回看 / 对照

开发中以根目录 `dist/` + `server/` 为工作区；需要对照 V1 时打开本目录同名文件 diff 即可。
